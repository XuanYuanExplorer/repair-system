# 学生宿舍服务平台 · 后端开发文档

**版本** V1.1 ｜ **框架** FastAPI（全异步）｜ **数据库** MySQL 8.0 ｜ **ORM** SQLAlchemy 2.0 async ｜ **缓存** Redis 7 ｜ **任务队列** ARQ

---

## 1. 技术选型与理由

| 层面 | 选型 | 版本 | 说明 |
|---|---|---|---|
| Web 框架 | FastAPI | ≥0.110 | 原生 async、自动 OpenAPI、Pydantic v2 校验 |
| ASGI | uvicorn + gunicorn | — | 生产用 gunicorn 管理 worker，`uvicorn.workers.UvicornWorker` |
| ORM | SQLAlchemy | 2.0 | 全量 `select()` 2.0 风格，禁止 1.x Query |
| 驱动 | `asyncmy` | ≥0.2.9 | 比 aiomysql 快，兼容 MySQL 8 caching_sha2_password |
| 迁移 | Alembic | ≥1.13 | 手写迁移 + `--autogenerate` 辅助 |
| 校验/配置 | pydantic v2 + pydantic-settings | — | 环境变量集中管理 |
| 认证 | python-jose[cryptography] + passlib[bcrypt] | — | JWT HS256；bcrypt rounds=12 |
| 缓存 | redis-py（async） | ≥5.0 | 验证码、黑名单、幂等键、限流 |
| 任务 | ARQ | ≥0.25 | 基于 Redis，纯 async，比 Celery 轻 |
| HTTP 客户端 | httpx | ≥0.27 | 调支付网关/短信，禁止 requests |
| 文件 | aiofiles + python-magic | — | 异步落盘 + magic bytes 校验 |
| 日志 | structlog | — | JSON 结构化 + trace_id |
| 序列化 | orjson（ORJSONResponse） | — | 统一响应包 |
| 限流 | slowapi 或自研 Redis 令牌桶 | — | 登录/短信/催单接口 |
| 测试 | pytest + pytest-asyncio + httpx.ASGITransport | — | 见测试文档 |

**为什么不用 Celery**：本项目定时任务只有 8 个轻量 job，ARQ 全异步、无额外 broker、与 FastAPI 生命周期一致，运维成本更低。若未来需要复杂编排再迁移。

## 4. 数据库设计

### 4.1 规范

- 引擎 InnoDB，字符集 `utf8mb4_0900_ai_ci`；金额一律 `DECIMAL(10,2)`（Python 侧 `Decimal`，禁用 float）。
- 时间统一 `DATETIME`，**存 UTC**，出口序列化为 ISO8601 带 `+08:00`；业务日（账单账期、值日周）用 `DATE`。
- 主键 `BIGINT UNSIGNED AUTO_INCREMENT`；对外暴露的编号用业务号（`order_no` / `bill_no` / `txn_no`），不暴露自增 ID。
- 所有表带 `created_at`、`updated_at`；软删除仅用于 `notices`（`deleted_at`），其余物理删除或状态位。
- 索引命名：`idx_` 普通、`uk_` 唯一、`fk_` 外键（MVP **不建物理外键**，用应用层约束 + 索引，便于分库与批量导入）。

### 5.1 工单状态机

| 当前 | 动作 | 目标 | 角色 | 前置条件 / 副作用 |
|---|---|---|---|---|
| — | `create` | `pending` | student | 校验 room 归属、时段容量 −1、写 `submit` 事件、发"已提交"消息 |
| `pending` | `accept` | `assigned` | admin | 必须指定 `worker_id`；写 `assign` 事件；发"已派单"消息 |
| `pending` | `cancel` | `cancelled` | student | 仅本人；释放时段容量；写 `cancel` 事件 |
| `pending` | `urge` | `pending` | student | 距上次 ≥5 分钟，否则 429；`urge_count+1` |
| `assigned` | `accept_job` | `fixing` | worker | 写 `accept_job`；回填 `accepted_at` |
| `assigned` | `start` | `fixing` | worker | 写 `visit` 事件；`started_at` |
| `assigned` | `cancel` | `cancelled` | student/admin | 开工前允许；释放时段；已派单消息作废 |
| `assigned` | `reassign` | `assigned` | admin | 换 `worker_id`，写 `assign` 事件 |
| `fixing` | `fix_done` | `verify` | worker/admin | 必填完工说明与 `material_fee`；写 `fix_done`；发"待确认"消息 |
| `fixing` | `cancel` | `cancelled` | admin | 学生不可取消进行中的工单 |
| `verify` | `verify_ok` | `done` | student | 写 `verify_ok`；`done_at`；触发 `repair.completed`（建材料费账单） |
| `verify` | `verify_fail` | `fixing` | student | 必填返修原因；`repair_round+1`；写 `verify_fail`；通知维修班组 |
| `verify` | `auto_close` | `done` | 系统 | 超 7 天未确认，`note="系统自动归档"`，标记 `auto_closed` |
| `done` / `cancelled` | * | — | — | 终态，任何迁移返回 `409 / 3001` |

**并发保护**：所有迁移统一走 `repair_service.transition()`：

```python
async def transition(session, order_id: int, action: str, actor: User, **kw):
    stmt = (
        update(RepairOrder)
        .where(RepairOrder.id == order_id,
               RepairOrder.status == ALLOWED[action].from_status,   # 条件更新，天然防并发
               RepairOrder.version == expected_version)              # 可选乐观锁
        .values(status=ALLOWED[action].to_status, version=RepairOrder.version + 1, **kw)
    )
    result = await session.execute(stmt)
    if result.rowcount == 0:
        raise BizError(ErrCode.ORDER_STATE_INVALID)   # 3001
    await session.execute(insert(RepairEvent).values(...))
```

### 5.2 领域事件（outbox）

| 事件 | 触发点 | 消费者动作 |
|---|---|---|
| `repair.created` | 创建工单同事务 | 通知宿管后台（站内消息给 admin 组）、释放/占用时段 |
| `repair.assigned` | 派单同事务 | 给学生发消息 + 短信（按偏好） |
| `repair.completed` | `verify_ok` 同事务 | **`material_fee > 0` 时建 material 账单**（来源 `source_type='repair_order'`, `source_id`）+ 通知 |
| `repair.fix_done` | 完工 | 给学生发"待确认"消息 |
| `bill.paid` | 支付成功 | 关闭提醒消息、可自动开票 |
| `bill.overdue` | 定时任务 | 发逾期提醒、计算滞纳金 |

写入模式：业务 `INSERT/UPDATE` 与 `INSERT outbox_events` 在同一 `async with session.begin()` 中提交，ARQ worker 每 5 秒扫 `status='pending' AND available_at<=now()` 消费，失败 `retry_count+1`，指数退避，5 次后置 `failed` 并告警。

### 5.3 账单金额规则

| 类型 | 计算 | 生成时机 |
|---|---|---|
| 超定额电费 | `(用量 − 定额) × 单价`，例 `(239−160)×2.00=158.00` | 每月 1 日抄表任务 |
| 住宿费 | 学年标准（配置项） | 学期初批量 |
| 维修材料费 | 工单 `material_fee` | `repair.completed` 事件 |
| 水费 | 同电费逻辑，独立定额 | 每月 |
| 罚金 | 人工录入 | 后台，不可合并支付、不可部分缴纳 |
| 滞纳金 | `ROUND(amount × 0.0005 × overdue_days, 2)`，封顶 `amount × 30%` | 逾期任务每日重算，写入 `late_fee`（不并入 `amount`） |

## 6. 权限模型

角色只有三种（`student` / `worker` / `admin`），**寝室长是派生权限**：`dorm_rooms.leader_id == current_user.id`，不新增角色，避免与宿管混淆。

| 能力 | student | 寝室长 | worker | admin |
|---|---|---|---|---|
| 查看/提交自己的工单、账单、消息 | ✅ | ✅ | — | — |
| 查看本寝信息、成员名单 | ✅ 只读 | ✅ 只读 | — | ✅ 全楼 |
| 编辑本寝公约 | ❌ 403 | ✅ | — | ✅ |
| 生成/调整值日排班 | ❌ 403 | ✅ | — | ✅ |
| 提交卫生整改 | ❌ | ✅ | — | ✅ |
| 提交入住/退宿申请 | ✅ 本人 | ✅ 本寝 | — | ✅ 审批 |
| 借还公共物品 | ✅ 登记本人 | ✅ 任意 | — | ✅ |
| 派单、完工、代确认 | ❌ | ❌ | 仅被派工单 | ✅ |
| 发布公告、回复反馈、生成账单 | ❌ | ❌ | — | ✅ |
| 查看他人账单/工单 | ❌ 403（IDOR 校验） | ❌ | ❌ | ✅ |

**实现**：

```python
# deps.py
async def get_current_user(token = Depends(oauth2_scheme), session = Depends(get_session)) -> User:
    payload = decode_token(token)                      # 校验签名/exp/type=access
    if await redis.exists(f"jwt:blacklist:{payload['jti']}"):
        raise BizError(ErrCode.TOKEN_REVOKED)          # 1002
    user = await session.get(User, int(payload["sub"]))
    if not user or user.status != 1:
        raise BizError(ErrCode.UNAUTHORIZED)           # 1001
    return user

def require_role(*roles):
    async def _dep(user: User = Depends(get_current_user)) -> User:
        if user.role not in roles:
            raise BizError(ErrCode.FORBIDDEN)          # 1003
        return user
    return _dep

async def require_room_leader(room_id: int, user: User, session) -> None:
    room = await session.get(DormRoom, room_id)
    if not room or room.leader_id != user.id:
        raise BizError(ErrCode.FORBIDDEN)
```

**IDOR 三件套**（每个资源接口必做）：① 资源存在性 404；② 归属校验 `resource.student_id == user.id` 否则 403（注意：不要返回 404 掩盖，测试用例要求 403）；③ 状态守卫。

## 7. 接口规范

### 7.1 约定

- 前缀 `/api/v1`；除 `/auth/*`、`/public/*` 外全部要求 `Authorization: Bearer <access_token>`。
- `Content-Type: application/json`；上传用 `multipart/form-data`。
- 时间 ISO8601（`2024-06-12T18:03:26+08:00`）；金额字符串（`"158.00"`）避免浮点误差。
- 分页参数 `page`（默认 1）、`page_size`（默认 20，上限 50）；响应 `{items,total,page,page_size,has_more}`。
- 写操作支持 `Idempotency-Key` 头（支付、提交工单必须）。

### 7.2 统一响应包

```json
{ "code": 0, "message": "ok", "data": { }, "trace_id": "b3f1c2d4e5a6" }
```

```json
{ "code": 3002, "message": "该时段已约满，请选择其他时段", "data": null, "trace_id": "..." }
```

HTTP 状态码与业务码同时使用：**HTTP 表达语义**（200/201/400/401/403/404/409/422/429/500），**code 表达具体原因**。前端只对 `code` 做分支，对 HTTP 做兜底。

### 7.3 错误码表

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| 0 | 200/201 | 成功 | — |
| 1001 | 401 | 未登录或 token 无效 | 清 token → 登录页 |
| 1002 | 401 | token 已过期/被吊销 | 尝试 refresh，失败跳登录 |
| 1003 | 403 | 无权限 | Toast「无操作权限」 |
| 1004 | 429 | 请求过于频繁 | Toast 提示稍后再试 |
| 2001 | 422 | 学号不存在或非本校在册 | 学号框红字 |

### 8.2 JWT 与刷新

- access：`{sub, role, jti, type:"access", exp:+2h}`；refresh：`{sub, jti, type:"refresh", exp:+7d}`，其 `sha256` 存 `refresh_tokens`。
- **轮换**：每次 refresh 生成新 refresh 并 `revoked_at=now, replaced_by=新hash`；旧 refresh 复用即判定盗用，吊销该用户全部 refresh 并写审计日志。
- 登出：access 的 `jti` 进黑名单（TTL=剩余有效期），refresh 直接 revoke。

```python
async def rotate_refresh(session, raw_refresh: str) -> tuple[str, str]:
    payload = decode_token(raw_refresh, expect="refresh")
    h = sha256(raw_refresh)
    row = await session.scalar(select(RefreshToken).where(RefreshToken.token_hash == h).with_for_update())
    if not row or row.revoked_at or row.expires_at < utcnow():
        await revoke_all(session, payload["sub"]); raise BizError(ErrCode.TOKEN_REVOKED)
    new_raw, new_h = new_pair()
    row.revoked_at, row.replaced_by = utcnow(), new_h
    session.add(RefreshToken(user_id=row.user_id, token_hash=new_h, device_id=row.device_id,
                             expires_at=utcnow() + timedelta(days=settings.refresh_token_days)))
    await session.commit()
    return new_raw, new_access(row.user_id)
```

```python
        raise BizError(ErrCode.SLOT_FULL)     # 3002
```
- 单条 `UPDATE ... WHERE booked < capacity` 由 InnoDB 行锁保证原子性，**不需要先 SELECT 再判断**（那是最常见的超卖写法）。
- 取消工单时 `booked = booked - 1`（`GREATEST(booked-1, 0)`）。
- 时段表由定时任务提前 14 天生成，缺失时按默认容量即时创建。

```python
    await session.commit()

    params = await gateway.create_order(txn.txn_no, amount, channel)   # httpx.AsyncClient
```

```python
async def query_result(session, txn_no: str, user) -> dict:
    txn = await session.scalar(select(PaymentTransaction).where(
        PaymentTransaction.txn_no == txn_no, PaymentTransaction.user_id == user.id).with_for_update())
    if not txn: raise BizError(ErrCode.NOT_FOUND)

    if txn.status in ("created", "paying"):
        try:
            remote = await gateway.query(txn.txn_no)       # 只信网关，不信前端回调
        except httpx.HTTPError:
            await session.rollback()
            raise BizError(ErrCode.GATEWAY_UNAVAILABLE)    # 4004 → 前端继续轮询
        txn.query_count += 1; txn.last_query_at = utcnow()
        if remote.status == "SUCCESS":
            await mark_paid(session, txn, remote)          # 见下
        elif remote.status == "FAIL":
            txn.status = "failed"; txn.fail_reason = remote.reason
        elif txn.expire_at < utcnow():
            txn.status = "closed"
        await session.commit()
    return serialize(txn)


async def mark_paid(session, txn, remote):
    if txn.status == "success":                 # 幂等：重复回调直接返回
        return
    txn.status, txn.paid_at, txn.gateway_txn_id = "success", utcnow(), remote.txn_id
    bill_ids = [r.bill_id for r in await session.scalars(
        select(PaymentTxnBill).where(PaymentTxnBill.txn_id == txn.id))]
    res = await session.execute(update(Bill).where(Bill.id.in_(bill_ids), Bill.status.in_(["unpaid","overdue"]))
                                .values(status="paid", paid_at=utcnow()))
    if res.rowcount != len(bill_ids):           # 有账单已被别的流水付掉 → 需人工退款
        logger.error("double_pay", txn=txn.txn_no, expected=len(bill_ids), affected=res.rowcount)
        raise BizError(ErrCode.PAY_CONFLICT)
    session.add(OutboxEvent(event_type="bill.paid", payload={"txn_no": txn.txn_no, "bill_ids": bill_ids}))
```

**回调**：`POST /payment/callback/{channel}` 必须验签（微信 V3 平台证书、支付宝 RSA2），验签失败 401 且记审计日志；回调体**只用于触发查询**，金额与状态以 `gateway.query()` 为准。

### 8.5 文件上传

```python
ALLOWED = {"image/jpeg": "jpg", "image/png": "png", "image/heic": "heic", "video/mp4": "mp4"}

@router.post("/files")
async def upload(file: UploadFile, biz_type: str, user=Depends(get_current_user)):
    head = await file.read(2048)
    mime = magic.from_buffer(head, mime=True)              # 不信 Content-Type
    if mime not in ALLOWED: raise BizError(ErrCode.FILE_TYPE)
    limit = settings.max_video_mb if mime.startswith("video") else settings.max_image_mb
    name = f"{biz_type}/{date.today():%Y%m}/{uuid4().hex}.{ALLOWED[mime]}"
    path = Path(settings.upload_dir) / name; path.parent.mkdir(parents=True, exist_ok=True)
    size, hasher = 0, hashlib.sha256(head)
    async with aiofiles.open(path, "wb") as f:
        await f.write(head); size = len(head)
        while chunk := await file.read(1024 * 1024):
            size += len(chunk); hasher.update(chunk)
            if size > limit * 1024 * 1024:
                await f.close(); path.unlink(missing_ok=True)
                raise BizError(ErrCode.FILE_TOO_LARGE)     # 5002
            await f.write(chunk)
    row = File(owner_id=user.id, biz_type=biz_type, path=name, url=f"{settings.upload_base_url}/{name}",
               mime=mime, size=size, sha256=hasher.hexdigest())
    session.add(row); await session.commit()
    return ok({"id": row.id, "url": row.url, "mime": mime, "size": size})
```
- 同一 `sha256` 直接复用已有 URL（秒传 + 去重）。
- 校验归属：`media_urls` 里的 URL 必须属于当前用户，防止盗链他人图片。

## 9. 并发、一致性与幂等专题

| 场景 | 风险 | 方案 |
|---|---|---|
| 双击提交报修 | 两张工单、两次扣时段 | 前端按钮 loading + `uk_client_req(student_id, client_request_id)`；重复返回原工单 200 |
| 同账号多端同时支付同一账单 | 重复扣款 | `SELECT ... FOR UPDATE` 锁账单 + `UPDATE ... WHERE status IN ('unpaid','overdue')` 影响行数校验 + 网关侧 `out_trade_no` 唯一 |
| 支付回调与轮询并发 | 重复置为 paid / 重复开票 | `mark_paid` 幂等（`if txn.status == success: return`）+ `bills` 条件更新 + `receipts.uk_bill` |
| 派单并发（两个宿管同时派） | 覆盖师傅 | `UPDATE ... WHERE status='pending'`，rowcount=0 则提示已被处理 |
| 完工与取消并发 | 已完工被取消 | 状态机条件更新，天然互斥 |
| 逾期任务与用户支付并发 | 已支付仍被标逾期 | 任务 SQL 带 `status='unpaid'`，支付成功置 paid 后不再命中 |
| 消息重复推送 | 用户收到两条 | outbox 单次消费 + `messages(biz_type,biz_id,type,user_id)` 业务去重（写前查） |
| 批量生成账单 | 重复账单 | `uk_source(source_type, source_id, type)` 冲突即跳过 |

**事务边界**：一个 HTTP 请求一个事务，跨模块协作（如完工 → 建账单）走 outbox，不做跨表长事务。金额相关操作一律 `Decimal`，**禁止**在 Python 里用 float 求和。

## 11. 安全

| 项 | 措施 |
|---|---|
| 密码 | bcrypt rounds=12；强度规则见总览；禁止明文/可逆存储；改密后吊销全部 refresh |
| 登录防爆破 | 5 次失败锁 15 分钟（Redis 计数）；不区分"账号不存在/密码错误"提示 |
| 短信防刷 | 图形验证码（P2）+ 60s 间隔 + 单手机 5 次/日 + 单 IP 20 次/时 + 号段黑名单 |
| 越权 | 每个资源接口做归属校验；`student_id` 一律从 token 取，**绝不接受请求体传入** |
| SQL 注入 | 全参数化（SQLAlchemy 表达式）；`text()` 只允许无变量或绑定参数 |
| XSS | 前端渲染默认转义，`v-html` 禁用于用户内容；后端对 `description` 等做长度与字符过滤 |
| 上传 | magic bytes 白名单、大小限制、随机文件名、存储目录 `noexec`、独立域名、`Content-Disposition: attachment` |
| 支付 | 回调验签、金额服务端重算、`out_trade_no` 唯一、超时关单、对账任务（每日比对学生已缴与网关流水） |
| 敏感数据 | 日志与响应中手机号 `138****8880`、身份证不落库；`audit_logs` 记录管理端全部写操作 |
| 传输 | 全站 HTTPS + HSTS；Cookie 场景加 `Secure; SameSite=Lax` |
| 限流 | 全局 120 rpm/IP；登录 10 rpm；短信 1 rpm；支付查询 30 rpm |
| 依赖 | `pip-audit` 纳入 CI；禁用 `pickle`、`eval` |

## 12. 日志、监控与可观测

- **trace_id**：中间件生成（或透传 `X-Trace-Id`），写入日志上下文与响应体，前端错误上报带同一 id。
- **日志格式**：structlog JSON，字段 `ts, level, trace_id, user_id, method, path, status, duration_ms, biz_code`。慢请求（>500ms）单独 warn，`/home/summary`、`/repair/orders` 重点观察。
- **审计**：`assign / finish / notice.publish / feedback.reply / bill.generate / login.fail / password.change` 必写 `audit_logs`。
- **指标**（Prometheus）：QPS、P95、5xx 率、DB 连接池使用率、ARQ 队列长度、outbox 积压、支付成功率。
- **告警**：5xx > 1% 持续 5 分钟；outbox 积压 > 100；支付失败率 > 5%；`double_pay` 日志出现即 P0 电话告警。
- **健康检查**：`/healthz` 仅进程存活；`/readyz` 校验 DB + Redis。

## 14. 后端开发规范（Code Review Checklist）

1. 路由函数内无 SQL、无 `requests`、无 `time.sleep`；外部调用一律 `httpx.AsyncClient(timeout=...)`。
2. 所有查询用 `select()` 2.0 风格，列表接口必须分页，禁止无 `limit` 的全表扫描。
3. 金额用 `Decimal`，出参序列化为字符串；时间统一 UTC 存储、`+08:00` 输出。
4. 写接口必须考虑幂等与并发（条件更新或唯一约束），并在 docstring 注明幂等键。
5. 状态迁移只能通过 `repair_service.transition()`，禁止在 router 里直接 `order.status = ...`。
6. 新表必须同时提交：模型、Alembic 迁移（可回滚）、索引说明、种子数据。
7. 新接口必须同时提交：Pydantic In/Out、错误码、OpenAPI 示例（`examples=`）、pytest 用例。
8. 任何 `except Exception` 必须带日志与 trace_id，禁止裸 `pass`。
9. 敏感字段不进日志；`print` 禁止入库。
10. 每个 PR 附"接口变更说明"，前端据此更新 `types/api.d.ts`。

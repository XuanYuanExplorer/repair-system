# 学生宿舍服务平台 · 前端开发文档

**版本** V1.1 ｜ **框架** Vue 3.4（Composition API + `<script setup>` + TypeScript）｜ **构建** Vite 5 ｜ **路由** Vue Router 4 ｜ **状态** Pinia ｜ **请求** Axios ｜ **样式** CSS 变量 + 原生 CSS（不引入 UI 框架）

> 不引入 Element Plus：设计稿是强约束的黑白瑞士风格（1.5px 细线、衬线数字、零圆角、单点红），组件库的默认圆角/阴影/字号体系与之冲突，改造成本高于自研 19 个组件。仅日期选择、签名等复杂交互在需要时按需引入。

**硬性规则**

| 规则 | 说明 |
|---|---|
| 圆角 | 全局 0；仅头像（50%）、未读徽标（9px）、手机外壳（预览用）例外 |
| 阴影 | 禁止。层级靠 1.5px 线 + `--panel` 底色区分 |
| 颜色 | 除上述 7 色外不新增；红色只用于"进行中/故障/逾期/主 CTA"，同一屏不超过 2 处 |
| 线宽 | 只有 1.5px 与 1px，禁止 2px/3px 边框 |
| 字距 | 英文小标 `.18em~.34em`；正文 0；数字用 serif + `tabular-nums` |
| 数字 | 金额、工单号、评分统一 `font-family:var(--serif); font-variant-numeric:tabular-nums` |
| 图标 | 内联 SVG，`stroke:currentColor; stroke-width:1.7; fill:none`，20×20，禁止图标字体 |
| 交互态 | 按下 `opacity:.6`；禁用 `opacity:.35` + `cursor:not-allowed`；无 hover 放大/位移 |

**守卫逻辑**

```ts
router.beforeEach(async (to) => {
  const auth = useAuthStore()
  document.title = to.meta.title ? `${to.meta.title} · 宿舍服务平台` : '宿舍服务平台'

  if (to.meta.auth && !auth.accessToken) {
    // 有 refresh 时先尝试静默续期，避免刷新页面即被踢
    if (!(await auth.tryRefresh())) return { name: 'login', query: { redirect: to.fullPath } }
  }
  if (to.meta.guest && auth.accessToken) return { name: 'home' }
  if (to.meta.leaderOnly && !auth.isLeader) return { name: 'home' }   // 寝室长页兜底
  return true
})
```

- `scrollBehavior`：`savedPosition ? savedPosition : { top: 0 }`。
- `keepAlive`：仅 `repair-list`、`payment` 两个列表页，`<router-view v-slot="{ Component }"><keep-alive :include="['RepairList','PaymentCenter']">`；从详情返回时保留滚动位置与筛选条件，通过 `onActivated` 判断是否需要刷新（用 `needsRefresh` 标记而非每次都请求）。
- 路由级分包：每个 view 都是 `() => import()`，首屏只加载 login/home + 基础组件。

## 4. 请求层

### 4.1 Axios 实例

```ts
// api/client.ts
export const client = axios.create({
  baseURL: import.meta.env.VITE_API_BASE,      // https://api.example.edu/api/v1
  timeout: 15000,
})

client.interceptors.request.use((cfg) => {
  const auth = useAuthStore()
  if (auth.accessToken) cfg.headers.Authorization = `Bearer ${auth.accessToken}`
  cfg.headers['X-Client'] = 'h5/1.1'
  return cfg
})
```

### 4.2 响应解包 + 401 单飞刷新

```ts
let refreshing: Promise<string | null> | null = null
const pending: Array<(t: string | null) => void> = []

client.interceptors.response.use(
  (res) => {
    const body = res.data
    if (body.code === 0) return body.data           // 业务层只拿 data
    return Promise.reject(new BizError(body.code, body.message, body.trace_id))
  },
  async (err) => {
    const { response, config } = err
    if (response?.status === 401 && !config._retry) {
      config._retry = true
      refreshing ??= useAuthStore().refresh().finally(() => { refreshing = null })
      const token = await refreshing
      // 并发请求排队，等同一个刷新结果，避免刷新风暴
      if (token) { config.headers.Authorization = `Bearer ${token}`; return client(config) }
      useAuthStore().clear(); router.replace({ name: 'login', query: { redirect: router.currentRoute.value.fullPath } })
    }
    if (response?.status === 429) toast('操作太频繁，请稍后再试')
    if (!response) toast('网络异常，请检查网络后重试')
    if (response?.status >= 500) toast('服务暂时不可用')
    return Promise.reject(err)
  },
)
```

### 4.3 错误处理约定

| 场景 | 处理方式 |
|---|---|
| 业务码 1001/1002 | 静默刷新 → 失败跳登录，不弹 toast |
| 3001 状态不允许 | 弹「该工单状态已变更」+ 自动刷新详情 |
| 3002 时段已满 | 就地刷新时段列表，高亮原选项为「已约满」 |
| 3003 催单冷却 | 按钮进入倒计时（读响应里的 `retry_after`） |
| 4001 账单已支付 | 刷新列表 + toast「该账单已支付」 |
| 422 表单类 | 由表单组件就地红字，不用全局 toast |
| 500/网络 | `ErrorRetry` 组件 + 手动重试按钮 |

**统一三态**：所有异步区块必须有 `loading`（骨架）/ `empty`（`EmptyState`）/ `error`（`ErrorRetry`）三态，禁止白屏或纯文字「加载中」。

### 4.4 类型生成

```bash
npx openapi-typescript http://localhost:8000/api/v1/openapi.json -o src/api/types.ts
```
CI 中比对 `types.ts` 与后端 OpenAPI 是否一致，不一致则失败——这是前后端契约不漂移的唯一可靠手段。

### 5.2 各页规格

#### 01 登录 `views/auth/Login.vue` ★
- **数据**：`GET /public/notices/latest`（公告条）、`POST /auth/login`。
- **结构**：品牌 kicker → serif 主标题「宿舍服务平台」→ 学校名 → 学号/手机 `BField`（默认值 `20223601` 仅 demo）→ 密码 `BField` + `SHOW` 切换 → 记住登录 `BCheckbox` + 忘记密码右侧链接 → 黑色 `BButton`「登 录 · LOG IN」（字距 .24em）→ `OR` 分隔 → 描边按钮「微信/企业微信扫码登录」（P1 置灰，点击 toast「即将开放」）→ 「还没有账号？立即注册 →」→ 底部红色左边框公告条。
- **校验**：账号非空、密码 ≥6；错误码 2005 在表单上方红字「账号或密码错误」，2006 显示锁定倒计时并禁用按钮。
- **记住登录**：勾选 → refresh 存 `localStorage`（7d）；不勾 → 存 `sessionStorage`（关闭浏览器失效）。access 一律 `sessionStorage`（防长期驻留）。
- **成功**：`auth.setSession()` → 若 `redirect` 存在且为站内路径则 `router.replace(redirect)`，否则 `replace('/')`；同时预取 `/home/summary`（不阻塞跳转）。

#### 02 注册 / 身份认证 `views/auth/Register.vue` ★
- **数据**：`GET /auth/check-student`（学号失焦触发）、`POST /auth/register`。
- **交互**：四字段（学号/姓名/手机号/设置密码）+ 密码强度条（`STRONG 强 / MEDIUM 中 / WEAK 弱`，三段色块，红→墨→墨，实心段数 1/2/3）。
- **强度算法**（与后端一致）：长度 <6 或纯数字/纯字母 → 弱（不可提交）；≥6 且含字母+数字 → 中；≥8 且含字母+数字+符号 → 强。
- **核验面板**：提交成功后不跳转，就地展示 `VERIFY` 面板——「住宿记录匹配成功，已自动绑定 3 号楼 · 412 室 · 床位 3（下铺）／无需手动选择，信息不可自行修改」+ 深色 CTA「进入平台」。学号不匹配（2001/2002）时面板变红显示原因 + 「联系宿管」电话链接。
- **边界**：学号已被注册 → 提示「该学号已注册，请直接登录」；床位已被占用 → 提示联系宿管。

#### 03 重置密码 `views/auth/ResetPassword.vue`
- **数据**：`POST /auth/sms-code`、`POST /auth/reset-password`。
- **交互**：步骤指示「01 验证身份 / 02 设置新密码」（`BSegTabs` 只读态）；手机号 → 验证码（6 格输入，右侧「重新发送 59s」倒计时，`useCountdown` 在 `onUnmounted` 清理）→ 新密码（强度条）→ 确认密码。
- **校验**：两次不一致 → 红字「▲ 两次输入不一致，请重新输入」且提交禁用；新密码与最近 3 次重复 → 2004；底部灰字两条规则说明。
- **提交成功**：toast + `router.replace('/login')`，手机号带入账号框。

#### 04 首页 / 服务大厅 `views/home/Home.vue` ★
- **数据**：`GET /home/summary`（一次拿全）、`GET /notices?limit=2`。
- **版式（严格对齐设计稿）**：
  1. `DORM SERVICE` kicker；
  2. **衬线大问候**「412 室，上午好」——房间号来自 `summary`，问候语按当前小时切换（<11 上午好 / <14 中午好 / <18 下午好 / 否则 晚上好）；下方 11px「林晓阳 / 计算机学院 / 2022 级」；
  3. **双格面板**：左 `DUE 待缴 ¥158.00`，右 `ORDER 工单 1 单`，两格中间 1.5px 竖线，点击分别跳 `/payment`、`/repair/list?status=active`；
  4. **六宫格服务**（3×2，`svcgrid`）：我要报修 / 我的报修 / 在线缴费 / 我的寝室 / 值日排班 / 全部分类，图标 + 中文 + 英文小标，`我要报修` 图标为红色（首屏唯一红色图标）；
  5. **进行中工单卡**：`ORDER NO.0371` + 工单号 + 类别·位置 + `StatusTag` + 师傅与预计时间 + `ProgressSteps`（四段，当前段红色）；
  6. **黑色账单 CTA**：左侧「2024 年 6 月账单 ¥158.00」，右侧「立即缴纳」，整块深色，点击跳账单详情；

#### 05 报修提交 `views/repair/Submit.vue` ★
- **数据**：`GET /repair/slots?date=`、`POST /files`、`POST /repair/orders`。
- **表单结构**：

- **红点**：底部 Tab「我的」与顶部铃铛共用 `badge.unreadTotal`；进入页面不自动全部已读（保留手动，与设计稿一致）。

#### 19 个人中心 `views/profile/Profile.vue` ★
- **数据**：`GET /profile`、`PUT /profile`、`GET /auth/devices`。
- **结构**：`PROFILE` → 大头像（serif 姓氏）+ 姓名 + 副行「计算机学院 2022 级 · 3 号楼 412 室」+ 右侧「编辑资料」描边小按钮 → `认证信息 VERIFIED`（学号 / 学院·班级 / 宿舍·床位 三行，**右侧无箭头、无编辑图标、不可聚焦**，颜色略浅以示只读）→ `账号与安全 SECURITY`：修改密码 / 换绑手机号（副行脱敏手机）/ 登录设备与安全记录（右侧数字 2）/ 紧急联系人（副行「林父 · 139****5521」）/ 退出登录（红色文字，居中）→ 底部灰字版本与学校名。
- **交互**：退出登录 → 二次确认「退出后需重新登录」→ `POST /auth/logout` → 清 store → `replace('/login')`（不清除已填表单的登录页历史）。
- **编辑资料**：独立页 `Edit.vue`，仅头像（上传裁剪）、性别、紧急联系人、邮箱可改；学号/姓名/宿舍字段 disabled 且带锁图标，提交时前端不发这些字段，后端也拒绝。

#### 20 意见反馈 `views/feedback/Feedback.vue`
- **数据**：`POST /feedbacks`、`GET /feedbacks`、`GET /repair/orders?status=done`（关联工单下拉）。
- **结构**：`FEEDBACK` + 「意见反馈 / 投诉建议」→ `反馈类型 TYPE` 四个 chip（服务态度/维修质量/收费疑问/设施建议）→ `关联工单 LINK`（点击弹 `BSheet` 选择已完成工单，显示「WX20240612-0371 · 空调不制冷」；不关联时显示「不关联工单」）→ `问题描述 DESC`（`64/300` 计数）→ `上传图片 MEDIA 1/4` → 黑色「提交反馈」→ `我的反馈 HISTORY`：`FB0612-02 · 收费疑问` + 「宿管中心受理中 · 预计 2 个工作日回复」+ 右侧状态标签（处理中/满意）；已回复的可展开看官方回复并对结果打满意度（五星）。
- **校验**：类型必选、描述 10–300 字；未选类型提交 → 类型区红字提示。
- **提交后**：清空表单并刷新历史列表，toast「反馈已提交，可在下方查看进度」。

#### 21 帮助中心 `views/help/Help.vue`
- **数据**：`GET /help/faqs?q=`、`GET /help/hotlines`。
- **结构**：`HELP CENTER` + 「帮助中心」→ 搜索框（placeholder「搜索问题，如「跳闸」「发票」」，300ms debounce）→ `常见问题 FAQ`：折叠项 `FaqAccordion`（`01 · 报修后多久上门？` 加粗，右侧 + / −；展开显示答案；「自助」标签用小号红字描边）→ `服务电话 HOTLINE` 两行（`宿管中心 7×24 小时 0510-8818 6112`、`维修班组 08:00–20:00 0510-8818 9553`，点击 `tel:`）→ 底部红色实心按钮「紧急情况 · 一键拨号」（拨宿管中心）。
- **交互**：搜索命中为空 → 「没有找到相关问题，试试「报修」「电费」」+ 两个快捷标签；FAQ 展开不请求后端（答案已在列表里）。

// utils/format.ts
export const fmtMoney = (v: string | number) =>
  `¥${Number(v).toLocaleString('zh-CN', { minimumFractionDigits: 2, maximumFractionDigits: 2 })}`
export const fmtTime = (iso: string) => dayjs(iso).format('MM-DD HH:mm')
export const fmtRelative = (iso: string) => {
  const h = dayjs().diff(dayjs(iso), 'hour')
  if (h < 1) return `${dayjs().diff(dayjs(iso), 'minute')} 分钟前`
  if (h < 24) return `${h} 小时前`
  return h < 48 ? '昨天' : dayjs(iso).format('MM-DD')
}

## 7. 移动端适配

| 项 | 方案 |
|---|---|
| 基准宽度 | 375px 设计稿；`html{font-size:calc(100vw/375*16)}`，组件内用 `rem`（1rem=16px@375），或直接用 `px` + `clamp` 控制字号上下限 |
| 安全区 | Tab 栏 `padding-bottom: calc(24px + env(safe-area-inset-bottom))`；吸底条同理 |
| 视口高度 | `100dvh` 优先，回退 `100vh`；iOS 键盘弹起时用 `visualViewport` 监听调整输入区位置 |
| 输入框 | `font-size:16px` 防 iOS 自动缩放（视觉上用 `transform:scale(.875)` 保持 14px 观感），`inputmode` 按类型设置（`numeric`/`tel`） |
| 点击延迟 | `<meta name="format-detection" content="telephone=no">`；按钮 `touch-action:manipulation` |
| 滚动 | 列表用原生滚动 + `-webkit-overflow-scrolling:touch`；禁止页面级横向滚动（`overflow-x:hidden`） |
| 长文本 | 工单号、金额 `word-break:break-all`；标题 `-webkit-line-clamp:2` |
| 图片 | `loading="lazy"` + `decoding="async"` + 固定宽高比容器防抖动 |
| 深色模式 | **不做**（校方要求纯白纸面风格） |
| 横屏 | 锁定竖屏提示（可选）+ 布局仍可用 |
| 微信内置浏览器 | 处理 `WeixinJSBridgeReady`（支付）、`history.pushState` 返回拦截（表单页离开二次确认） |

|---|---|---|

## 9. 代码规范

- `<script setup lang="ts">` + `defineProps<Props>()`；组件名 PascalCase，文件同名。
- 状态只放在需要的地方：页面内 `ref`，跨页 `Pinia`，**不滥用全局 store**。
- 所有 `setInterval/setTimeout/addEventListener` 必须在 `onUnmounted`/`onDeactivated` 清理（支付轮询、验证码倒计时、聊天轮询是三个高危点）。
- 请求函数集中在 `api/*.ts`，返回已解包的 `data`，组件不直接调 `client`。
- 枚举文案与颜色统一走 `utils/dict.ts`，禁止在模板里写 `status === 'fixing' ? '维修中' : ...`。
- 样式一律 `scoped` + CSS 变量，禁止行内 style（除动态宽度百分比）；禁止 `!important`。
- ESLint（`vue/vue3-recommended` + `@typescript-eslint`）+ Prettier + Stylelint，`husky` pre-commit 跑 `lint-staged`。
- 提交前必须 `vue-tsc --noEmit` 通过（CI 卡口）。
- 可访问性：按钮用 `<button>`，图标按钮带 `aria-label`，表单 `label for` 关联，颜色不作为唯一信息载体（状态同时有文字）。
